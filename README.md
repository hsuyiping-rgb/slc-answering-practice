# 理答練功房：學習共同體六大理答策略・課堂語音模擬

一個讓老師**一個人、戴著耳機、對著麥克風**反覆練習「理答」的網頁。

畫面上是一段國小五年級的真實課堂情境，某位學生剛說完一句話——接下來換你開口，說出你身為老師的下一句。系統會聽你說了什麼，告訴你這句話用的是哪一種理答策略，再讓你聽見學生接下來的反應。不同的一句話，會把課堂帶到不同的地方。

👉 **網址：https://slc-answering.web.app**

理答策略的定義取自《學習領導下的學習共同體進階手冊 2.0 版》；情境改編自作者本人執教的五年級數學公開課〈省水馬桶〉實錄。

## 使用前準備

| 需要 | 說明 |
|---|---|
| 瀏覽器 | 電腦版 Chrome 或 Edge（實測環境；其他瀏覽器未逐一驗證） |
| 麥克風 | 筆電內建或外接皆可 |
| **耳機** | 強烈建議。用喇叭外放時，學生的聲音可能被麥克風收進去 |
| 網路 | 需要連線（語音辨識與判定在雲端進行） |
| 帳號 | **不需要**，也不用登入 |

第一次按下「開始這一回合」時，瀏覽器會詢問是否允許使用麥克風，請按「允許」。

## 練一回合的流程

### 1. 選一張情境卡

畫面最上方是情境卡清單，點一張就會切換。每張卡是同一堂課裡的一個真實時刻：

| 卡 | 標題 | 練習重點 | 開口的學生 |
|---|---|---|---|
| C01 | 聽不懂的那句話 | 釐清＋深究 | 小宇說到一半卡住了 |
| C02 | 題目給了哪些線索？ | 轉引 | 小靚說出第一條線索 |
| C03 | 你聽到小靚說的嗎？ | 轉問 | 小靚把解題步驟講完整了 |
| C04 | 先算什麼？ | 反問 | 小宇說要先算省下多少水費 |
| C05 | 是「度」嗎？ | 提示 | 小宇沒發現要換單位 |
| C06 | 哪裡不一樣？ | 串聯（轉問） | 小賢說出他們組的算式 |

「練習重點」是這張卡設計時瞄準的策略，**不是標準答案**。任何一種說法都會有對應的學生反應。

### 2. 讀前情

卡片上方的文字交代這堂課進行到哪裡、學生們剛剛在做什麼。

**（可選）事前自選策略**：前情下方有六個策略按鈕。如果你想先決定「這一回合我打算用轉問」，就點一下。回合結束後，系統會拿你的預想和你實際說出口的話比一比——這是練「想的」和「說的」是否一致。不選也完全沒關係。

### 3. 按「開始這一回合」

學生會先開口說一句話（有語音，也有文字）。**學生說完的那一刻，錄音就開始了。**

### 4. 換你了

畫面會出現「換你了。」和一個持續往上跳的秒數。

- 像在真實教室裡一樣，說出你的下一句話。
- **不說話也可以。** 等待本身就是一種理答動作。錄音不會因為安靜而自動停止，也沒有倒數計時。
- 說完了（或等夠了），按 **「說完了，停止」**。

> 🔒 **錄音只用來轉成文字，轉完立刻刪除，不會存到任何地方。**

### 5. 看回饋

回饋分成三塊，由上往下：

**等待**：你在學生說完後過了幾秒才開口。這裡只描述發生了什麼，不評好壞——接得快、等得久，各有它在教室裡的樣子。

**第一層：策略辨識**：你這一句話屬於哪一種策略，以及系統的判斷依據（會引用你話裡的關鍵片段）。
- 這一層**有對錯**：如果你心裡想的是轉問，說出口卻是反問，這裡會指出來，因為那是概念上的混淆。
- 如果你事前選了策略，這裡會對照你的預想和實際說出口的話。

**第二層：接下來發生的事**：學生會用語音回應你的那一句話，並附上一段「後果」說明——這句話把課堂帶往哪裡、話留在誰身上。
- 這一層**不評對錯**。系統不會說你「應該」選哪一個策略；它只讓你看見不同選擇會走向不同的課堂。
- **再聽一次**：重播學生的回應。
- **聽聽看另一條路**：播放另一種理答會引出的學生反應，讓你對照兩條路的差別。

### 6. 再練一次

按「再練一次」回到開頭，同一張卡可以一直重練。換一種說法、換一個等待的長度，聽聽看學生會怎麼接。

## 什麼時候會請你「再說一次」

有些情況系統不會播放學生語音，而是請你重新說一次：

- **聽不清楚**：收音太小、雜音太多，辨識不出你說了什麼。
- **這一句在這個時刻不成立**：例如學生根本還沒提出主張，就無法「反問」他。系統會說明原因，並舉一個可以怎麼說的例子。
- **只有評價、沒有交出發言權**：例如只說了「好，很好。」——這句話還沒有把話交給任何人，教室會停在等老師的下一句。

這不是扣分，只是這一句還沒有讓課堂往下走。

## 六大理答策略速查

| 策略 | 一句話說明 |
|---|---|
| **轉引** | 同一個問題連續請不同學生說出不同想法，老師先不評價、繼續收集（高原策略）。 |
| **轉問** | 把某位同學的發言或疑問，交給另一位同學回應、補充或評論。 |
| **反問** | 學生已提出明確主張，老師把它丟回去讓學生自己判斷，不說對錯。 |
| **提示** | 給線索，縮短學生與答案之間的距離。老師提供了新資訊。 |
| **釐清** | 老師（或全班）沒聽懂，請學生把同一件事再說一次。要的是同一份內容的另一次表達。 |
| **深究** | 老師聽懂了，但要學生往前推一格：說出理由、說得更具體。要的是多出來的內容。 |

另外，如果老師直接把答案說出來，系統會告訴你「這一句不在六個策略裡」，並讓你聽見學生接下來的反應。

## 我的練習紀錄

頁面最下方的「我的練習紀錄」可以展開，看到：

- 你用過各種策略的次數分布
- 平均等待秒數、最長等待秒數

| 按鈕 | 作用 |
|---|---|
| 匯出 JSON | 把紀錄下載成檔案，可以自己留存，或帶去備課社群討論 |
| 清除紀錄 | 刪除這台裝置上的所有紀錄 |

**紀錄只存在你這台裝置的瀏覽器裡**，只有判定結果（策略、等待秒數），**沒有錄音、也沒有你說的逐字文字**。換電腦、換瀏覽器、使用無痕視窗或清除瀏覽器資料，紀錄就不會跟著。

## 隱私與設計原則

- **錄音絕不保存**：你的聲音只在送去轉成文字的那一刻存在，轉完立即丟棄。
- **不需登入、不蒐集個資**：沒有帳號，伺服器端不留下任何屬於你的紀錄。
- **學生皆為化名**：課堂中的學生一律以「小＋名字末字」呈現（小宇、小靚、小賢、小妃……），語音為 AI 合成。
- **系統不替你的選擇打分數**：這套教材要老師戒掉「提問－回答－評價」的單向問答，所以練功房本身也不做這件事。

## 常見問題

**Q：按了開始卻沒有反應，或出現麥克風錯誤？**
檢查瀏覽器網址列左側的權限設定，確認麥克風是「允許」；也確認沒有其他程式（如視訊會議）正佔用麥克風。

**Q：我明明沒說話，系統卻判成我說了什麼？**
多半是喇叭外放時學生的聲音被麥克風收進去了，戴上耳機即可改善。

**Q：我明明等了很久，等待秒數卻很短？**
等待期間的清喉嚨、敲鍵盤、挪椅子等聲音，可能被當成你開口了。練習時盡量保持安靜。

**Q：學生的聲音聽起來和上次不一樣？**
語音偶爾會更新。如果懷疑是舊版，按 Ctrl＋F5 強制重新整理。

**Q：判定結果和我想的不一樣？**
判定由 AI 完成，準確度很高，但不是百分之百。若你認為判錯了，那正是一個好問題——同一句話為什麼可以被理解成兩種策略？這很值得帶到備課社群討論。

## 給開發者

本資料夾是這個系統的原始碼。技術架構與進度請看：

- `規格_情境卡C0*.md`：六張情境卡的設計規格（分支、後果文案、判定邊界）
- [`judge/README.md`](judge/README.md)：判定器的驗收方法、本機 emulator 啟動方式、真麥克風測試紀錄

簡要架構：`public/`（前端，Firebase Hosting）→ `functions/`（Cloud Functions 代理：Groq Whisper 語音辨識、Gemini 策略判定）。學生語音以 Gemini TTS 預先合成，放在 `public/audio/<卡>/`。API 金鑰只存在後端 Secret Manager，前端不含任何金鑰。

本機開發時在網址加上 `?mock=1` 可用手動模擬面板代替後端判定；在網址加上 `?card=c03` 可直接開啟指定情境卡。
